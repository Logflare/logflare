# Webhook

The Webhook backend will send batched events to a desired HTTP(S) destination. 

## Behaviour and configurations
### Configuration

The following values are required when creating a webhook backend:

- `url`: (`string`, required) a valid HTTP(S) endpoint.

Optional values:

- `format`: (`string`, optional) the payload encoding, either `json` (default) or `ndjson`.
- `headers`: (`map`, optional) headers sent with each request. For a bearer token, set the `authorization` header to `Bearer <token>`.
- `gzip`: (`boolean`, optional, default `true`) compress the request body with gzip. The request sets the `content-encoding: gzip` header. Disable this when the receiver does not decompress request bodies.

### Request 
The request made will be a `POST`.

### Payload format

With `format` set to `json`, each batch is sent as a JSON array of events.

With `format` set to `ndjson`, each batch is sent as newline-delimited JSON, one event per line. The request uses the `application/x-ndjson` content type. A user-configured `content-type` header takes precedence.

### Batching

Events will be sent in batches of up to 250, with intervals of up to 1 second.

## Webhook v2

The Webhook v2 backend (`webhook_v2`) sends the same requests as the Webhook backend. It uses one shared pipeline for each backend, not one pipeline for each source. Use it for a backend with many attached sources or a high event rate.

### Configuration

Webhook v2 accepts all Webhook configuration values. It adds one optional value:

- `batch_size`: (`integer`, optional, default `1000`) the maximum number of events in one request. The range is `1` to `10000`.

### Batching

All sources attached to the backend share the batches. A request contains up to `batch_size` events, with intervals of up to 1 second. The payload does not identify the source of an event.

### Retries

Webhook v2 sends a failed batch again one time when the failure is transient:

- a `408`, a `429`, or a `5xx` response status
- a connection error or a timeout

Each transient failure counts toward a circuit breaker for the backend. The circuit breaker opens after 20 transient failures in 30 seconds. It stays open for 30 seconds. Webhook v2 does not send a failed batch again while the circuit breaker is open. It still sends new batches.

Webhook v2 drops a batch when the receiver returns any other `4xx` response status. An event that does not encode to JSON is dropped alone. The other events of the batch are sent.
